# RC39 Backplane Clone mode

Opt-in memory map for titles written for the RC39 clone of the VZ200. It is
**off unless you ask for it at launch**; without `--rc39` the emulator is a
stock VZ200, or a VZ200 + Benn Venn SD loader if you give it `--dos-rom` /
`--sd-*`, exactly as before.

    ./run.sh rc39                          # stock BIOS + RC39 map
    ./run.sh rc39 --rc39-rom ten_k.bin     # also fill the 10K ROM window
    java -jar jar/vz200.jar --os-rom BIOS/VZ200_20.bin --rc39

Options: `--rc39`, `--rc39-rom FILE` (raw <=10K or .VZ; implies `--rc39`),
`--rc39-trace` (prints bank-register writes; implies `--rc39`).
`--rc39` cannot be combined with the SD loader options (the program exits
with an error): they are separate hardware models.

## What is modelled (from memory_map.md)

| CPU range | Behaviour |
|---|---|
| 0000-3FFF | BASIC ROM |
| 4000-67FF | bit 3 of the bank register: 1 = SRAM (bank 1's bottom 10K), 0 = ROM image |
| 6800-6FFF | MMIO (unchanged stock keyboard / tape / sound / video latch) |
| 7000-77FF | VRAM (unchanged) |
| 7800-BFFF | fixed RAM (identity-mapped into the low 64K of the 128K SRAM) |
| C000-FFFF | window onto one of 8 x 16K banks, selected by bits 0-2 |

Port 0x70 (decoded as any port with low byte 0x70-0x7F) is the bank register,
power-on value 0. Overlaps fall out of one rule (fixed regions = identity map
into the low 64K of SRAM, only the C000 window substitutes the bank number):
bank 1 top 2K (F800-FFFF in the window) *is* fixed RAM 7800-7FFF, where the OS
keeps its environment and stack; bank 2 *is* 8000-BFFF; bank 3 is physically
C000-FFFF.

## Could NOT be confirmed without real hardware

* **Writes to 4000-67FF while the ROM is selected** (bit 3 = 0): modelled as
  reaching the SRAM (reads still return ROM). memory_map.md does not say.
* **Reading port 0x70** is modelled as floating high ($FF).
* **Contents of the 10K ROM**: not in the memory map; empty ($FF) unless you
  supply `--rc39-rom`.
* SRAM power-on contents are zero here; on real SRAM they are undefined, so a
  title that depends on cleared RAM at boot could behave differently.
* No timing, bus contention or video-access-slot behaviour is modelled.
* Bank-switch correctness was tested against *this reading* of memory_map.md,
  not against a real RC39 board.
